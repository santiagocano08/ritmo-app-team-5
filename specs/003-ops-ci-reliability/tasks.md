# Tasks: CI Gate, Ingestion Resilience and Freshness Signal

**Input**: Design documents from `/specs/003-ops-ci-reliability/`

**Prerequisites**: plan.md, spec.md (approved: spec `2bb565f`, plan `bbf06e8`), research.md (R1–R15 and "Gate decisions"), data-model.md, contracts/, quickstart.md

**Tests**: ON (project default; the spec and constitution do not opt out, and FR-028 requires a failing test or check before every behavior change).

**Organization**: the four phases of the plan, in order: CI (US1) → resilience (US2) → freshness (US3) → docs and drill rerun. Each phase ends with a verification task and can be committed on its own. There are no separate Setup or Foundational phases: no new service, dependency, table or contract is added (research R15), so nothing blocks the stories except the order below.

## Format: `- [ ] T### [P?] [US?] Description with file paths (FR/SC ids)`

- **[P]**: can run in parallel (different files, no dependency on an unfinished task).
- **[US1..US3]**: user story of `spec.md`. Phase 4 serves the documentation deliverables (FR-024 to FR-027) and carries no story label.
- **✂**: on the cut list (see the table at the end). Cut inside a phase, never the phase itself.
- Paths are relative to the repository root. Agents never commit or push; the human commits each phase.
- **Red rule**: every implementation task names the test task it turns green. A test task is only done when it has been run and seen to **fail for the stated reason**.
- **Commands**: *Andon* = `docker compose --profile tools build tests && docker compose --profile tools run --rm tests` (unchanged, CI-ready). *Host suite* = `uv run pytest` (full suite with the 80 % gate; tests marked `live` skip themselves unless `-m live` is passed, as `src/data/tests/integration/test_refresh_live.py:20` does, so the plain command never stops `db`). Run them **one at a time**, never together.
- **Verify project**: every verification step and live test that starts, stops or resets a compose stack uses a dedicated project name, `export COMPOSE_PROJECT_NAME=pulsoflota-verify` (the drill uses `pulsoflota-drill`). No task runs `down -v` on the developer's default project; cleanup is `docker compose down -v` **under the dedicated project only**, or plain `docker compose down` without `-v`.
- **Untouched check** (identical in every phase verification task, M6): `git status --short` and `git diff --stat` show no change to `contracts/`, `src/data/ingestion/bronze.py`, `src/data/ingestion/validate.py`, `src/data/db/init/002_bronze.sql` (and no change to `001`, `003`, `004`, `005` init scripts; `006_ops.sql` is the only new init script, and only in Phase 3), `.github/CODEOWNERS`, `.drill-input/` and `drill-out/`; the only `docs/adr` change is the one allowed in T035. Files outside the phase's own list are reported, not accepted.
- Every file under `docs/ops/`, `scripts/drill/` and `.github/workflows/` created here is new; `.drill-input/` is local input only and is **never committed**.
